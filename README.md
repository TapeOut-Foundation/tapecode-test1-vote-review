> **致社区**：此前的“历史严格票”审核条件偏严——固定名单只来自第一轮的投票人，后来才加入的朋友没有机会被审核，这对很多真心参与的成员并不公平。TapeOut 社区基金会为此诚挚致歉，也感谢大家的耐心。比赛结束后，我们一个账号一个账号地重新复核，并把过程公开在这里。

## 我们是怎么做的

1. **读公示表**：三轮汇总与逐笔明细交叉核对一致。三套口径：原始票、快照票（3 票/地址）、历史严格票（快照 ∩ 首轮冻结的 67 人名单）。
2. **找到问题**：67 人名单恰好等于第一轮的严格有效投票人，**后来才出现的账号没有被审核的机会**（056 方 14 个、003 方 2 个）。
3. **定标准**（见下），**所有账号用同一套标准**：决赛里未进名单的 53 个快照账号，以及全部 82 个 1 票地址。
4. **只读核查 X 内容**：在已登录 X 的浏览器里扫描每个账号的主页和回复页，逐个判定并附推文链接；边缘账号由基金会成员逐个确认。全程没有点赞、转发、关注、发帖或回复。
5. **重算并公开所有口径**：每个合格的快照账号 3 票、1 票地址 1 票，同时公开所有口径下的结果和边缘账号的敏感性。

### 标准
**有效**（真实的生态内容或互动，需实质性互动或原创）：
1. 与 @Blonskr、@TapeOutCF 等生态账号真实回复、评论或带字引用；
2. 原创含 TapeOut、TapeCode、Test1、BEM、NAND、LATCH、矿机、流片 等内容；
3. 与已知 Builder / Core Supporter 真实互动；
4. 有明确捐赠或开发 TapeOut 相关工具 / 游戏的记录。

**无效**：仅点赞 / 纯转发 / 关注；仅单词提及；空泛回复；与 TapeOut 无关的其他项目内容；**提交时间高度集中的批量投票批次**（按基金会数据库口径）。间接讨论可计入，但要判断是否真正参与了社区讨论。

### 结果明细
| | 快照账号（3 票） | | | 1 票地址 | | |
|---|---|---|---|---|---|---|
| | 计入 | 不计入 | 存疑 | 通过 | 无有效内容 | 提交时间高度集中 |
| 056 | 11 | 27 | 2 | 6 | 5 | 67 |
| 003 | 7 | 4 | 2 | 1 | 3 | 0 |

- “存疑”是账号不存在 / 已冻结，没有内容可核，不计票。
- 提交时间高度集中的 67 个账号，依据基金会数据库的提交时间记录（公示表没有时间戳，第三方无法复验）。**为避免点名，公开材料不列名单**；认为自己被误判的可以申诉（见下）。

### 标准与方法的调整记录
| 阶段 | 调整 |
|---|---|
| 标准对齐 | 单词提及不算；间接讨论要看是否真参与社区；需实质性互动或原创 |
| 纠正一个错误 | 第一轮只扫了回复页，漏掉原创帖，@EasonOnly 被误判；重扫主页后发现他 46 条自发帖里 18 条含 TapeOut/BEM，并写明捐赠两张 NFT，改判计入；此后一律“主页 + 回复页”重扫 |
| 成员确认边缘账号 | 部分边缘账号由基金会成员逐个确认并计入；抽奖类、无有效内容的账号不计入 |
| 扩展范围 | 把审核范围从快照账号扩展到全部 1 票地址，并加入“提交时间高度集中”一条 |

我们**不对任何账号作“有组织行为”的判断**：投票模式本身既可能是有组织，也可能是支持者的第二选择，数据分不出来，只看内容是否满足标准。

## 局限
- 抓取脚本主要看每个账号主页和回复页的近期内容（约 6–14 屏），更早的内容可能没逐条看。
- 转推识别未经校准：脚本对所有账号的转推数都是 0，但已知 @EasonOnly 有转推；转推不改变最终结果。
- “提交时间高度集中”依赖基金会数据库，第三方无法复验。
- 4 个存疑账号（不存在 / 已冻结）无内容可查；账号后来改名或注销的无法回溯。
- @liberty_SaulGm 在我们可见的内容里只有泛泛夸赞，故未计入（口径 D+ 给出若计入的结果 79:84）。
